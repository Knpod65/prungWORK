# สเปกหน้าจอและพฤติกรรมของระบบตรวจสอบชั่วโมง TA (ฉบับละเอียด)

เอกสารนี้อธิบาย **หน้าตาและการทำงานของทุกหน้าจอ** ตามโค้ดใน `src/` (ฐานคอมมิต `4e14309`) ทุกตัวอย่าง id ข้อความ ตัวเลข และสี คัดจากโค้ดจริง ใช้เทียบกับ script ที่ deploy อยู่ว่าตรงกันหรือไม่ หรือใช้เป็นแบบเมื่อต้องสร้างใหม่

อ้างอิงที่เกี่ยวข้อง: `DESIGN.md` (ทิศทางดีไซน์ Verdant Park Trust), `PRODUCT.md` (ผู้ใช้และวัตถุประสงค์), `docs/manual/manual.md` (คู่มือผู้ใช้พร้อมภาพ)

---

## 0. ภาพรวม

| หัวข้อ | รายละเอียด |
|---|---|
| ชนิดแอป | Google Apps Script Web app (`doGet`) ไฟล์เดียวแบบ SPA เรนเดอร์ด้วย JavaScript ฝั่งเบราว์เซอร์ |
| ผู้ใช้ | นักศึกษา TA (role `student`) และเจ้าหน้าที่ (role `staff`) |
| การยืนยันตัวตน | OTP 6 หลักส่งอีเมล @cmu.ac.th ไม่มีบัญชีหรือรหัสผ่าน |
| ที่เก็บข้อมูล | Google Sheets (แท็บแคบๆ แยกตามหน้าที่) ตั้งค่าที่แท็บ `Config` |
| OTP และ session | `CacheService` (หมดอายุเอง) ไม่เขียนลงชีต |
| Deploy | Execute as **Me**, Access **Anyone** |
| ภาษาหน้าจอ | ไทยทั้งหมด |

### 0.1 ไฟล์ฝั่งหน้าเว็บ

| ไฟล์ | หน้าที่ |
|---|---|
| `src/index.html` | โครงหน้า (พื้นหลัง SVG, แถบบน, `<main id="app">`, ส่วนท้าย, ตัวประกาศ `#live`) และฝังค่า `BOOT` |

### 1.3 รูปทรง

- ปุ่ม ช่องอีเมล และปุ่มกรอง เป็นแคปซูล (`border-radius: 9999px`) สูง **44px** ทุกปุ่ม (เป้าสัมผัสขั้นต่ำ)
- การ์ด ช่องข้อความ (`textarea`): มุม 16px, กล่องย่อย 12px
- ปุ่ม/ช่องที่โฟกัส: เส้นขอบ 2px น้ำเงิน เว้นจากขอบ 2px พร้อมวงขาวบางๆ

### 1.4 พื้นหลังและเอฟเฟกต์

- พื้นหลัง SVG ตรึงเต็มจอ (ฟ้าไล่เขียว ดวงอาทิตย์จาง เนิน 3 ชั้น บ่อน้ำ ต้นไม้) มีเฉพาะ `aria-hidden`
- **วงรีวาดมือ**: เส้นสีเขียวอ่อนครอบคำเด่นของหัวเรื่อง ("ชั่วโมง" / "รหัส") วาดขึ้นครั้งเดียว 1.1 วินาที หน่วง 0.3 วินาที ปิดอนิเมชันเมื่อผู้ใช้ตั้ง `prefers-reduced-motion`
- ข้อความที่อาจทับภาพพื้นหลังมีแผ่นรองสีเขียวเข้มโปร่ง (`--scrim`) เพื่อให้อ่านชัดทุกขนาดจอ

## 3. แผนผังสถานะของหน้า

```
                 ┌─────────────┐  ส่งอีเมลสำเร็จ   ┌────────────┐  รหัสถูกต้อง
   เปิดลิงก์ ───▶│ A. กรอกอีเมล │─────────────────▶│ B. กรอกรหัส │──────────────┐
                 └─────────────┘◀── เปลี่ยนอีเมล ──└────────────┘              │
                        ▲                                                       ▼
                        │ ออกจากระบบ / เซสชันหมดอายุ                    ┌──────────────┐
                        └──────────────────────────────────────────────│ boot(): apiMe │
                                                                        └──────┬───────┘
                                                role = student │               │ role = staff
                                                 ┌─────────────▼───┐   ┌───────▼────────────┐
                                                 │ C. หน้านักศึกษา  │   │ D. แดชบอร์ดเจ้าหน้าที่ │
                                                 └─────────────────┘   └────────────────────┘
```

- มี token อยู่แล้วตอนโหลดหน้า → ข้าม A, B ไปที่ `boot()` ทันที (แสดง "กำลังโหลด…")
- `apiMe` ล้มเหลวด้วย `AUTH` → ล้าง token แล้วกลับ A (เงียบ) ถ้าเป็น error อื่นกลับ A พร้อมข้อความ
- เจ้าหน้าที่ที่อีเมลอยู่ทั้งใน `Staff` และ `Student` จะได้ role `staff` (เห็นแดชบอร์ด ไม่เห็นหน้านักศึกษา)

## 4. หน้า A: กรอกอีเมล

```
              ตรวจสอบ(ชั่วโมง) TA
                  ของคุณ
   เข้าสู่ระบบด้วยอีเมล @cmu.ac.th เราจะส่งรหัส OTP ไปให้

        ┌──────────────────────────────┐
        │ name@cmu.ac.th               │ ①
        └──────────────────────────────┘
        ใช้อีเมลที่ได้รับสิทธิ์ในระบบ ไม่ต้องใช้รหัสผ่าน CMU
        ┌──────────────────────────────┐
        │         รับรหัส OTP           │ ②
        └──────────────────────────────┘
        (พื้นที่ข้อความ error #err)
```

| # | องค์ประกอบ | รายละเอียด |
|---|---|---|
| ① | ช่องอีเมล `#email` | `type=email`, `inputmode=email`, `autocomplete=email`, placeholder `name@cmu.ac.th`, `aria-label` "อีเมลมหาวิทยาลัย", โฟกัสอัตโนมัติเมื่อเปิดหน้า |
| – | คำแนะนำ `.hint` | "ใช้อีเมลที่ได้รับสิทธิ์ในระบบ ไม่ต้องใช้รหัสผ่าน CMU" |
| ② | ปุ่ม `submit` | "รับรหัส OTP" (ปุ่มหลักสีน้ำเงิน) กด Enter ในช่องอีเมลก็ส่งได้ |
| – | `#err` | `role=alert` แสดงข้อความ error / ข้อความจากการหมดเซสชัน |

**ลำดับการทำงานเมื่อกด**
1. ตัดช่องว่าง แปลงเป็นตัวพิมพ์เล็ก ตรวจรูปแบบ `^[^\s@]+@[^\s@]+\.[^\s@]+$` ไม่ผ่าน → "รูปแบบอีเมลไม่ถูกต้อง" และโฟกัสช่องเดิม (ยังไม่เรียก server)
2. ปุ่มเปลี่ยนเป็นหมุน + "กำลังส่ง…" และกดซ้ำไม่ได้ ระหว่างเรียก `apiRequestOtp`
3. สำเร็จ → ไปหน้า B พร้อมข้อความเขียว "ส่งรหัสแล้ว กรุณาตรวจอีเมลและกรอกรหัส 6 หลัก"
4. ล้มเหลว → แสดงข้อความตามตาราง error (หัวข้อ 9) ที่ `#err`

หมายเหตุ: ถ้าอีเมลไม่อยู่ในระบบ server ตอบ "สำเร็จ" เหมือนกัน แต่ไม่ส่งอีเมล (กันการเดาว่าใครมีบัญชี)

## 5. หน้า B: กรอกรหัส OTP

```
                 กรอก(รหัส) OTP
   ┌─────────────────────────────────────────────┐
   │ หากอีเมลนี้อยู่ในระบบ เราส่งรหัส 6 หลักไปที่      │ ← .otp-delivery

   ┌─────────────────────────────────────────────┐
   │                 0 0 0 0 0 0                  │ ①
   └─────────────────────────────────────────────┘
              รหัสนี้เหลือเวลา 9:41 นาที             ②
        ส่งรหัสแล้ว กรุณาตรวจอีเมลและกรอกรหัส 6 หลัก    ← #err (เขียว/แดง)
   ┌─────────────────────────────────────────────┐
   │             ยืนยันและเข้าสู่ระบบ                │ ③
   └─────────────────────────────────────────────┘

   ┌─────────────────────────────────────────────┐
   │ ยังไม่พบอีเมล?                               │ ⑥
   │ รอประมาณ 1–2 นาที แล้วตรวจโฟลเดอร์ Junk/Spam   │
   │ หรือค้นหาคำว่า “ระบบตรวจสอบชั่วโมง TA” ...      │
   └─────────────────────────────────────────────┘
   เพื่อความปลอดภัย เจ้าหน้าที่จะไม่ขอรหัส OTP จากคุณทางโทรศัพท์หรือแชท
```

| # | องค์ประกอบ | รายละเอียด |
|---|---|---|
| – | กล่องผู้รับ `.otp-delivery` | แสดงอีเมลที่ใช้ (ตัวหนา) |
| ① | ช่องรหัส `#code` | ตัวเลขขนาด 26px ตัวหนา เว้นตัวอักษรกว้าง สูง 62px, `maxlength=6`, `inputmode=numeric`, `autocomplete=one-time-code` (มือถือเติมรหัสจาก SMS/อีเมลได้), โฟกัสอัตโนมัติ **ตัวอักษรที่ไม่ใช่ตัวเลขถูกลบทิ้งทันที** |
| ② | นับถอยหลัง `#cd` (`role=timer`) | เริ่ม "รหัสใช้ได้ N นาที" แล้วนับทุกวินาทีเป็น `m:ss` หมดเวลา → "รหัสหมดอายุแล้ว กรุณากด “ส่งรหัสใหม่”" (สีแดงอ่อน) และ **ปุ่มยืนยันถูกปิด** |
| – | ข้อความสถานะ `#err` (`role=alert`) | สีเขียว = สำเร็จ (`.ok`) สีแดงอ่อน = ผิดพลาด (`.bad`) |
| ③ | ปุ่ม `#verify` | "ยืนยันและเข้าสู่ระบบ" |
| ④ | ปุ่ม `#resend` | ปิดอยู่และเขียน "ส่งใหม่ได้ใน m:ss" นับถอยหลัง `OTP_RESEND_SEC` วินาที (ปกติ 60) จากนั้นเปิดเป็น "ส่งรหัสใหม่" |
| ⑤ | ปุ่ม `#back` | "เปลี่ยนอีเมล" กลับหน้า A |
| ⑥ | กล่องช่วยเหลือ `#help` | ข้อความตายตัว + ชื่อผู้ส่งจาก `BOOT.sender` |
| – | คำเตือน `.otp-security` | "เพื่อความปลอดภัย เจ้าหน้าที่จะไม่ขอรหัส OTP จากคุณทางโทรศัพท์หรือแชท" |

**เมื่อกด "ยืนยันและเข้าสู่ระบบ"**
1. ปุ่มถูกปิด (รหัสหมดอายุ) → ไม่ทำอะไร
2. รหัสไม่ครบ 6 หลัก → "กรุณากรอกรหัสยืนยันให้ครบ 6 หลัก" (ไม่เรียก server)
3. ปุ่มเป็นหมุน + "กำลังตรวจสอบ…" เรียก `apiVerifyOtp(email, code)`
4. สำเร็จ → เก็บ token, หยุด timer, เรียก `boot()` ไปหน้า C หรือ D
5. ล้มเหลว → แสดงข้อความ (หัวข้อ 9) ที่ `#err`, โฟกัสและเลือกข้อความในช่องรหัสเพื่อพิมพ์ทับได้ทันที

**เมื่อกด "ส่งรหัสใหม่"**: ปุ่มเปลี่ยนเป็น "กำลังส่ง…" สำเร็จ → เรนเดอร์หน้า B ใหม่ (รีเซ็ตทั้งสอง timer) พร้อมข้อความเขียว "ส่งรหัสใหม่แล้ว กรุณาใช้รหัสล่าสุดเท่านั้น" ล้มเหลว → ปุ่มกลับเป็นกดได้ และมีข้อความแดง

**กติกาฝั่ง server ที่ผู้ใช้เห็นผล**: รหัสใช้ได้ `OTP_TTL_MIN` นาที (ปกติ 10) ครั้งเดียว กรอกผิดได้ `OTP_MAX_TRIES` ครั้ง (ปกติ 5) แล้วรหัสถูกทิ้ง รหัสใหม่จะแทนที่รหัสเก่าเสมอ

## 6. หน้า C: นักศึกษา

### 6.1 โครงหน้า (ยังไม่ตอบ)

```
              ตรวจสอบ(ชั่วโมง) TA
 ┌───────────────────────────────────────────────────────────┐
 │ สมหญิง รักเรียน                                            │ ← .who-name
 │ รหัสนักศึกษา 691910001 · ภาคเรียนที่ 1/2569                 │ ← .meta
 │ ┌────────────┐ ┌────────────┐ ┌─────────────────────────┐ │
```

| องค์ประกอบ | id/class | รายละเอียด |
|---|---|---|
| ชื่อ | `.who-name` | ชื่อ-สกุลจากแท็บ `Student` |
| รหัส/ภาคเรียน | `.meta` | "รหัสนักศึกษา {id} · ภาคเรียนที่ {term}" |
| กล่องรอบ | `.stat` (หนึ่งกล่องต่อรอบ) | หัวกล่อง "รอบที่ N" ตัวเลขชั่วโมง (ทศนิยมได้สูงสุด 2 ตำแหน่ง เช่น 16.5) จำนวนกล่องตามจำนวนรอบในแท็บ `Hours` |
| กล่องรวม | `.stat.total` | "ชั่วโมงรวม" พื้นเขียวเข้ม ตัวขาว (เน้น) และกินเต็มแถวบนมือถือ |
| คำถาม | `#q1` | "ชั่วโมงรวม {รวม} ชั่วโมง ถูกต้องหรือไม่" |
| ปุ่มยืนยัน | `#yes` | "ถูกต้อง ยืนยัน" (ปุ่มหลัก น้ำเงิน) |
| ปุ่มรายงาน | `#no` | "ไม่ถูกต้อง รายงาน" (ปุ่มขอบเทา พื้นขาว) |

**กรณีไม่มีข้อมูลชั่วโมง** (ไม่มีแถวใน `Hours` ของภาคเรียนนี้): การ์ดแสดงชื่อ และข้อความ "ยังไม่มีข้อมูลชั่วโมงของคุณในภาคเรียนนี้" ไม่มีปุ่ม

### 6.2 กด "ถูกต้อง ยืนยัน"
1. ปุ่มหมุนระหว่างเรียก `apiSubmit(token, 'confirmed', '')`
2. สำเร็จ → เรนเดอร์หน้าใหม่ มีกล่องสถานะ (6.4) โฟกัสที่กล่องสถานะ และประกาศเสียง "บันทึกการยืนยันชั่วโมงแล้ว"
3. `AUTH` → กลับหน้า A พร้อม "เซสชันหมดอายุ กรุณาเข้าสู่ระบบใหม่" ข้อความอื่น → แสดงในฟอร์มรายงาน

### 6.3 กด "ไม่ถูกต้อง รายงาน": ฟอร์มรายงาน

```
 [ ถูกต้อง ยืนยัน ]  [ ไม่ถูกต้อง รายงาน ]
 ┌───────────────────────────────────────────────────────┐
 │ บอกเจ้าหน้าที่ว่าไม่ถูกต้องตรงไหน เช่น รอบที่ 2 ควรเป็น 50 ชั่วโมง │ ①
 └───────────────────────────────────────────────────────┘
                                                  0/1000  ②
 (ข้อความ error สีแดงเข้ม #err)
 [ ส่งรายงาน ] ③  [ ยกเลิก ] ④
```

| # | องค์ประกอบ | รายละเอียด |
|---|---|---|
| ① | `#detail` | `textarea` สูงอย่างน้อย 110px ปรับความสูงได้ `maxlength=1000` `aria-label` "รายละเอียดที่ไม่ถูกต้อง" โฟกัสอัตโนมัติเมื่อเปิด |
| ② | `#n` | ตัวนับตัวอักษร `n/1000` |
| ③ | `#send` | "ส่งรายงาน" (ปุ่มสีแดง `--destructive`) |
| ④ | `#cancel` | "ยกเลิก" ปิดฟอร์ม ไม่ส่งอะไร ถ้ายังไม่เคยตอบ โฟกัสกลับปุ่ม `#no` ถ้าเคยตอบแล้ว ซ่อนส่วนคำถามกลับไปที่ "เปลี่ยนคำตอบ" |

**กฎการส่ง**: ตัดช่องว่างหัวท้ายก่อนนับ ต้องมีอย่างน้อย `REPORT_MIN_CHARS` ตัวอักษร (ปกติ 10) ไม่ถึง → "กรุณาอธิบายให้ละเอียดขึ้นอีกเล็กน้อย" (สีแดงเข้ม ไม่เรียก server) ผ่าน → `apiSubmit(token, 'reported', detail)` สำเร็จ → กล่องสถานะ + ประกาศเสียง "ส่งรายงานถึงเจ้าหน้าที่แล้ว" และ server ส่งอีเมลแจ้งเจ้าหน้าที่ (ความล้มเหลวของอีเมลไม่ทำให้การส่งรายงานล้ม)

### 6.4 กล่องสถานะหลังตอบ `#status`

```
 ┌─────────────────────────────────────────────────────┐
 │ [ยืนยันแล้ว] 3 พ.ย. 2569 15:00                         │ ← ป้ายเขียวอ่อน
 │ เปลี่ยนคำตอบ                                          │ ← #change
 └─────────────────────────────────────────────────────┘
 (ส่วนคำถาม #ask ถูกซ่อน)
```

| กรณี | ป้าย | เนื้อหา |
|---|---|---|
| ยืนยันแล้ว | "ยืนยันแล้ว" เขียวอ่อน | วันเวลา (โซน Asia/Bangkok รูปแบบไทย พ.ศ.) + ลิงก์ "เปลี่ยนคำตอบ" |
| รายงานแล้ว | "รายงานแล้ว" แดง | วันเวลา + ข้อความที่ส่ง (รักษาการขึ้นบรรทัด) + ลิงก์ "เปลี่ยนคำตอบ" |
| ชั่วโมงถูกปรับหลังตอบ (`stale`) | ป้ายตามคำตอบเดิม | ข้อความหนา "ชั่วโมงถูกปรับปรุงหลังคุณตอบ" + "(ตอนนั้น N ชม.) กรุณาตรวจสอบและตอบอีกครั้ง" **ไม่มีลิงก์เปลี่ยนคำตอบ แต่ส่วนคำถามและปุ่มแสดงอยู่เลย** |

- "เปลี่ยนคำตอบ" `#change` ทำให้ส่วนคำถาม (`#ask`) กลับมาแสดงและโฟกัสที่คำถาม
- คำตอบเก่าไม่ถูกลบ ระบบเก็บเป็นประวัติ (แท็บ `Response`) และถือแถวล่าสุดเป็นสถานะปัจจุบัน

### 6.5 มือถือ (≤ 720px)
- ปุ่มใน `.actions` กว้างเต็มแถว (คนละบรรทัด)
- กล่อง "ชั่วโมงรวม" กินเต็มแถวด้านล่างกล่องรอบ
- ชื่อผู้ใช้ในแถบบนถูกซ่อน เหลือปุ่มออกจากระบบ

### 7.1 แบนเนอร์ `#banner`
- แสดงเมื่อ `counts.newReports > 0` ข้อความ "มีนักศึกษารายงาน N รายการที่ยังไม่รับทราบ" (`role=alert`)
- ปุ่ม `#showRep` "ดูรายการ" → ตั้งตัวกรองเป็น "รายงาน" และโฟกัสปุ่มกรองนั้น
- สร้างใหม่เฉพาะเมื่อ **ตัวเลขเปลี่ยน** (การรีเฟรชอัตโนมัติจึงไม่ประกาศซ้ำให้ screen reader)

### 7.2 ช่องสรุป `#tiles`

| ช่อง | ค่า | หมายเหตุ |
|---|---|---|
| ยืนยันแล้ว | `confirmed / all` | เช่น `5 / 12` |
| รายงานไม่ถูกต้อง | `reported` | ตัวเลขสีแดงเมื่อมากกว่า 0 (นับ **ทั้งหมดที่ตอบว่ารายงาน** แม้รับทราบแล้ว) |
| ยังไม่ตอบ | `pending` | |

หมายเหตุ: ตัวเลขในแบนเนอร์ (ยังไม่รับทราบ) กับช่อง "รายงานไม่ถูกต้อง" ต่างกันได้ ช่องนี้นับทุกรายงาน ส่วนแบนเนอร์นับเฉพาะที่ยังไม่กดรับทราบ

### 7.3 เครื่องมือกรอง

| องค์ประกอบ | รายละเอียด |
|---|---|
| ช่องค้นหา `#q` | `type=search` placeholder "ค้นหาชื่อหรือรหัส" กรองทันทีที่พิมพ์ (ไม่เรียก server) ค้นชื่อแบบไม่สนตัวพิมพ์ และรหัสแบบมีคำนั้นอยู่ในรหัส เปลี่ยนแค่รายการ ไม่ทำให้ช่องค้นหาเสียโฟกัส |
| ปุ่มกรอง `data-f` | "ทั้งหมด" `all` · "รายงาน" `reported` · "ยังไม่ตอบ" `pending` · "ยืนยันแล้ว" `confirmed` ปุ่มที่เลือกมีสีเขียวเข้ม (`aria-pressed=true`) ใช้ร่วมกับช่องค้นหาได้ |

### 7.4 รายการนักศึกษา `#rows`
เรียงตามรหัสนักศึกษา แต่ละแถว (`.row`):

| คอลัมน์ | เนื้อหา |
|---|---|
| ชื่อ | ชื่อ-สกุล (ตัวหนา) + รหัสนักศึกษา (ตัวเล็กสีเทา) |
| รอบ 1, รอบ 2 … | ชั่วโมงแต่ละรอบ (`–` ถ้าไม่มีข้อมูลรอบนั้น) จำนวนคอลัมน์ขึ้นกับจำนวนรอบที่มีในข้อมูล |
| รวม | ชั่วโมงรวม (ตัวหนา) |
| สถานะ | ป้าย + วันเวลาที่ตอบล่าสุด (ถ้ามี) |

ป้ายสถานะ:

| ป้าย | สี | ความหมาย |
|---|---|---|
| ยืนยันแล้ว | เขียวอ่อน | คำตอบล่าสุดคือยืนยัน |
| รายงาน | แดง | คำตอบล่าสุดคือรายงาน (แถวขยายให้เห็นข้อความ) |
| ยังไม่ตอบ | เทา | ยังไม่มีคำตอบในภาคเรียนนี้ |
| ชม.เปลี่ยน | ขาวขอบเทา | (เพิ่มต่อท้ายป้ายหลัก) ชั่วโมงถูกแก้หลังนักศึกษาตอบ รอตอบใหม่ |

แถว "รายงาน" มีกล่อง `.detail`:
- ข้อความของนักศึกษา (คงการขึ้นบรรทัด)
- ปุ่ม "รับทราบ" `data-ack` (น้ำเงิน) → เรียก `apiAck` สำเร็จแล้วเปลี่ยนเป็นข้อความ "รับทราบแล้ว" แบนเนอร์ลดจำนวน และประกาศเสียง "รับทราบรายงานแล้ว" โฟกัสคงอยู่ที่ตำแหน่งเดิม
- ถ้ารับทราบไปแล้ว: แสดง "รับทราบแล้ว" แทนปุ่ม

ไม่พบรายการตามตัวกรอง → ข้อความ "ไม่พบรายการ"

### 7.5 การรีเฟรช
- รีเฟรชข้อมูลทุก **60 วินาที** เฉพาะตอนแท็บเปิดอยู่ และรีเฟรชทันทีเมื่อสลับกลับมาที่แท็บ
- แบนเนอร์ ช่องสรุป และรายการ ถูกวาดใหม่เฉพาะส่วนที่เนื้อหาเปลี่ยน ช่องค้นหา การพิมพ์ภาษาไทย (IME) และโฟกัสไม่หลุด
- ชื่อแท็บเบราว์เซอร์แสดงจำนวนรายงานที่ยังไม่รับทราบ เช่น `(3) ตรวจสอบชั่วโมง TA` กลับเป็นชื่อปกติเมื่อไม่มี หรือเมื่อออกจากระบบ
- ถ้าระหว่างรีเฟรชได้ `AUTH` (เซสชันหมด) → กลับหน้า A พร้อม "เซสชันหมดอายุ กรุณาเข้าสู่ระบบใหม่"

### 7.6 มือถือ (≤ 720px)
- หัวตารางถูกซ่อนทางสายตา (ยังอ่านได้ด้วย screen reader)
- แถวกลายเป็นการ์ดเรียงลง ตัวเลขแต่ละช่องมีป้ายนำหน้า เช่น "รอบ 1: 36", "รวม: 80"

## 8. การเข้าถึง (Accessibility) ที่ทำไว้แล้ว

| เรื่อง | วิธี |
|---|---|
| ป้ายช่องกรอก | ช่องอีเมลและรหัสมี `aria-label` / `label`, ช่องรายงานมี `aria-label` |
| ประกาศ error | `#err` เป็น `role=alert`, ผลการยืนยัน/รายงาน/รับทราบประกาศผ่าน `#live` |
| นับถอยหลัง | `#cd` เป็น `role=timer` |
| โฟกัส | โฟกัสอัตโนมัติที่ช่องแรกของแต่ละหน้า หลังตอบ โฟกัสที่กล่องสถานะ หลังรับทราบ โฟกัสคงที่เดิม |
| ปุ่มกำลังทำงาน | ตั้ง `aria-busy` และ `aria-label` "กำลังดำเนินการ" ล็อกความกว้างปุ่มกันขยับ |
| เป้าสัมผัส | ปุ่มและลิงก์สูงอย่างน้อย 44px |
| ตาราง | `role=table/row/cell/columnheader` พร้อมชื่อ "รายชื่อ TA และสถานะการยืนยัน" |
| หัวเรื่องซ่อน | แดชบอร์ดมี `h1` ที่เห็นเฉพาะ screen reader |
| ความคมชัด | ข้อความที่อยู่บนภาพพื้นหลังมีแผ่นรอง (scrim) |
| การเคลื่อนไหว | ปิดอนิเมชันวงรีเมื่อผู้ใช้ตั้งลดการเคลื่อนไหว |
| การกันข้อมูลฝัง | ข้อความจากผู้ใช้ทุกจุดผ่านฟังก์ชัน `esc()` ก่อนแสดง |

## 9. ข้อความ error ทั้งหมด (รหัส → ข้อความที่ผู้ใช้เห็น)

| รหัส | เกิดเมื่อ | ข้อความ |
|---|---|---|

| `AUTH` | token หมดอายุหรือไม่ถูกต้อง (ราว `SESSION_HOURS` ชม.) | เซสชันหมดอายุ กรุณาเข้าสู่ระบบใหม่ |

| `NETWORK` | เรียก server ไม่สำเร็จ | เชื่อมต่อไม่ได้ กรุณาลองใหม่ |
| `ERROR` และรหัสอื่น | ข้อผิดพลาดที่ไม่คาดคิด | เกิดข้อผิดพลาด กรุณาลองใหม่ |

## 10. สัญญา API (google.script.run)

ทุกฟังก์ชันคืน `{ ok: true, data }` หรือ `{ ok: false, code }` (ไม่โยน exception ไปที่หน้าเว็บ)

| ฟังก์ชัน | พารามิเตอร์ | สิทธิ์ | ผลลัพธ์ (`data`) |
|---|---|---|---|
| `apiRequestOtp` | `email` | ใครก็ได้ | `null` (ตอบสำเร็จเหมือนกันแม้อีเมลไม่อยู่ในระบบ) |
| `apiVerifyOtp` | `email, code` | ใครก็ได้ | `token` (สตริง) |
| `apiLogout` | `token` | – | `null` |
| `apiMe` | `token` | ผู้ล็อกอิน | `{ email, name, role, student? }` โดย `student = { id, term, hours:[{round,hours}], total, response }` |
| `apiSubmit` | `token, status, detail` | นักศึกษา | `student` (รูปแบบเดียวกับข้างบน) ปรับปรุงแล้ว |
| `apiDashboard` | `token` | เจ้าหน้าที่ | `{ term, rounds:[…], students:[…], counts }` |
| `apiAck` | `token, responseId` | เจ้าหน้าที่ | `dashboard` ล่าสุด |

`response` = `{ id, status('confirmed'|'reported'), detail, at(ISO), hoursSeen, stale }`

แถวใน `students[]` ของแดชบอร์ด: `{ id, name, hours:[{round,hours}], total, status('confirmed'|'reported'|'pending'), detail, at, responseId, acked, stale }`

`counts` = `{ all, confirmed, reported, pending, newReports }`

กติกา:
- `status` ที่ส่งเข้า `apiSubmit` ต้องเป็น `confirmed` หรือ `reported` เท่านั้น (อย่างอื่น → `BAD_STATUS`)
- ยืนยัน: ล้าง `detail` ทิ้ง รายงาน: ตัดช่องว่าง จำกัด 1,000 ตัวอักษร ต้องไม่สั้นกว่า `REPORT_MIN_CHARS`
- `hours_seen` บันทึกชั่วโมงรวม ณ ขณะตอบ ใช้ตัดสิน `stale`
- `apiAck` ซ้ำไม่ทำให้เกิดแถวซ้ำ

## 11. ข้อมูลที่หน้าจอพึ่งพา (แท็บในชีต)

| แท็บ | คอลัมน์ | หน้าจอที่ใช้ |
|---|---|---|
| `Config` | key, value | ค่า `BOOT` และพฤติกรรมทั้งระบบ |
| `Staff` | email, name | ตัดสิน role และผู้รับอีเมลแจ้งเตือน |
| `Student` | student_id, name, email | ชื่อ รหัส และอีเมลสำหรับรับ OTP |
| `Hours` | term, student_id, round, hours | กล่องชั่วโมงและแดชบอร์ด (หนึ่งแถวต่อคนต่อรอบ) |
| `Response` | response_id, term, student_id, status, hours_seen, detail, at | สถานะของนักศึกษา (ประวัติ เพิ่มต่อท้ายเท่านั้น) |
| `Ack` | response_id, by, at | การกด "รับทราบ" |

### คีย์ใน `Config` (ค่าเริ่มต้น)

| คีย์ | ค่าเริ่มต้น | ผลต่อหน้าจอ |
|---|---|---|
| `TERM` | `1/2569` | ภาคเรียนที่แสดงและใช้กรองข้อมูล |
| `TITLE` | ตรวจสอบชั่วโมง TA | ชื่อแถบบน |
| `FACULTY` | คณะรัฐศาสตร์และรัฐประศาสนศาสตร์ | ส่วนท้าย / อีเมล |
| `MAIL_SENDER_NAME` | ระบบตรวจสอบชั่วโมง TA | ชื่อผู้ส่งอีเมล และข้อความช่วยเหลือในหน้า B |
| `MAIL_FROM` / `MAIL_REPLY_TO` | `polsci.ecwp@gmail.com` | ผู้ส่ง/ที่ตอบกลับ (ว่าง = ใช้บัญชีเจ้าของสคริปต์) |
| `NOTIFY_EMAIL` | `TRUE` | ส่งอีเมลหาเจ้าหน้าที่เมื่อมีรายงาน |
| `OTP_TTL_MIN` | `10` | อายุรหัส |

| `OTP_RESEND_SEC` | `60` | เวลารอก่อนขอรหัสใหม่ |

หมายเหตุ: Google Sheets มักแปลงค่า `1/2569` เป็น "วันที่" ระบบอ่านกลับเป็น `1/2569` ให้เสมอ (`termOf_`) และ `setup()` ซ่อมค่าที่ถูกแปลงแล้ว

## 12. อีเมลที่ระบบส่ง

### 12.1 อีเมล OTP (ถึงผู้ขอรหัส)

| หัวข้อ | รายละเอียด |
|---|---|
| หัวเรื่อง | `รหัส OTP {รหัส} – {TITLE}` |
| ผู้ส่ง | `MAIL_SENDER_NAME` ในนาม `MAIL_FROM` (ถ้าใช้ไม่ได้ ส่งจากบัญชีเจ้าของสคริปต์) ตอบกลับไป `MAIL_REPLY_TO` |
| หน้าตา | กรอบเขียวเข้ม โลโก้ใบไม้ + ชื่อระบบ การ์ดขาว หัวข้อ "รหัส OTP ของคุณ" กล่องรหัสตัวใหญ่ (38px เว้นตัวอักษร) ป้ายเขียว "ใช้ได้ภายใน N นาที" + "และใช้ได้ครั้งเดียว" คำเตือน "อย่าบอกรหัสนี้กับผู้อื่น แม้จะอ้างว่าเป็นเจ้าหน้าที่" และชื่อคณะท้ายอีเมล |
| เทคนิค | ตารางและ inline style เท่านั้น (ไคลเอนต์อีเมลตัด `<style>`) ฟอนต์ระบบ มี preheader ซ่อนไว้ มีเนื้อความตัวอักษรล้วนสำรอง |

### 12.2 อีเมลแจ้งเตือนรายงาน (ถึงเจ้าหน้าที่ทุกคนในแท็บ `Staff`)

หัวเรื่อง: `[TA {TERM}] นักศึกษารายงานชั่วโมงไม่ถูกต้อง: {ชื่อ} ({รหัส})`
เนื้อหา: ชื่อ รหัส ชั่วโมงรวมในระบบ ข้อความรายงาน และลิงก์เปิดระบบ (ตัวอักษรล้วน)

## 13. ความปลอดภัยที่ผู้ใช้อาจสังเกตเห็น

- ไม่เปิดเผยว่าอีเมลใดอยู่ในระบบ (ตอบเหมือนกันทุกกรณีที่หน้า A)
- รหัส OTP เก็บเป็นค่าแฮช (HMAC) ไม่เก็บรหัสจริง ใช้ได้ครั้งเดียว เปรียบเทียบแบบเวลาคงที่
- สิทธิ์ตัดสินจากชีตทุกครั้งที่เรียก API (เพิ่ม/ลบเจ้าหน้าที่มีผลทันที)
- ข้อความจากผู้ใช้ถูก escape ก่อนแสดงทุกจุด
- ต้องมีสิทธิ์เจ้าหน้าที่จึงเรียก `apiDashboard` / `apiAck` ได้ (นักศึกษาได้ `FORBIDDEN`)
- การอนุญาต Gmail (`https://mail.google.com/`) กว้างกว่าที่จำเป็นต่อการส่งอย่างเดียว เพราะ `GmailApp` ต้องการ แนะนำให้ใช้บัญชีเจ้าของสคริปต์เฉพาะงานนี้
